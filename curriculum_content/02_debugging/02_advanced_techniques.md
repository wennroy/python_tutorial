## 🧠 核心概念：智能断点

### 1. 条件断点 (Conditional Breakpoints)

右键点击红色的断点 -> **Edit Breakpoint...**

你可以输入一个 Python 表达式，例如：
- `i == 9999`：只有当 `i` 等于 9999 时才暂停。
- `user_name == "admin"`：只有特定用户登录时才暂停。
- **Hit Count**: 输入 `10`，表示第 10 次运行到这里时暂停。

### 2. 日志点 (Logpoints) 💎

这是我最喜欢的功能！它允许你在**不修改代码**、**不暂停程序**的情况下打印日志。

#### 为什么不用 `print()`?
- **保持代码洁净**: 调试完不需要回头删除 `print` 语句，避免不小心把调试代码提交到 Git。
- **不破坏执行流**: 有些 Bug 涉及时间敏感逻辑（如网络请求超时、多线程竞争），暂停程序会破坏场景。Logpoints 几乎不影响程序运行速度。

#### 如何使用
1. 右键点击行号 -> **Add Logpoint...**
2. 输入要打印的消息。支持使用 `{}` 包裹 Python 表达式。

#### 💡 实用示例
- **查看变量值**: `Current value: {x}, Result: {calculate(x)}`
- **循环计数**: `Loop iteration: {i}`
- **简单逻辑**: `User {user.name} is active: {user.is_active}`

> **辨析**: Logpoints 是**临时**的调试工具，只在 VS Code 调试模式下有效。如果你需要永久记录程序运行状态（例如在服务器上记录错误日志），请使用 Python 标准库的 `logging` 模块（我们将在后续章节详细讲解）。

### 3. 异常断点 (Exception Breakpoints)

程序突然崩溃退出了，你甚至没来得及看清报错信息？
在 VS Code 的 **Breakpoints** 面板（通常在左下角），勾选 **Raised Exceptions**。

**效果**：一旦程序抛出任何异常（即使被 `try-except` 捕获了），调试器会立刻暂停在抛出异常的那一行。

## 💻 跨平台操作指南

虽然 Python 是跨平台的，但调试体验略有不同。

### Windows vs macOS 快捷键对照表

| 功能 | Windows / Linux | macOS |
|------|----------------|-------|
| 启动调试 | `F5` | `F5` |
| 单步跳过 (Step Over) | `F10` | `F10` |
| 单步调试 (Step Into) | `F11` | `F11` |
| 单步跳出 (Step Out) | `Shift + F11` | `Shift + F11` |
| 重启 | `Ctrl + Shift + F5` | `Cmd + Shift + F5` |
| 停止 | `Shift + F5` | `Shift + F5` |

> **提示**: 如果你的 F 键被系统功能（如调节亮度）占用了，记得按住 `Fn` 键，或者在系统设置里修改 F 键行为。

## ✅ 动手挑战

我们将使用 `exercise_02_02.py`。这是一个处理大量数据的脚本，其中有一条脏数据会导致程序崩溃。

**任务**：
1. 运行脚本，观察它崩溃。
2. 勾选 **Uncaught Exceptions** 断点，重新运行。
3. 程序应该会暂停在出错的那一行。
4. 观察变量，找出是哪条数据导致了问题。
5. 使用 **条件断点** (`data_id == "bad_id"`) 再次复现。
6. 使用 **Logpoint** 打印出所有处理过的数据 ID，而不修改代码。

## 📝 总结

- **条件断点**帮你跳过无关的循环。
- **Logpoints** 是优雅的 `print` 替代品。
- **异常断点** 是捕捉崩溃现场的神器。
